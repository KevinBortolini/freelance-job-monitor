## Windows workbook-write correction

The user successfully installed base dependencies using Python 3.12 in Windows PowerShell, but the first demo failed with the safe workbook-write error. Inspection identified a Windows-incompatible file-sync handle: the temporary workbook was reopened read-only before `os.fsync`. It now uses `r+b`, as Windows requires a writable descriptor. A regression test enforcing that requirement failed before the fix and passed afterward; a simulated flush failure also confirms that existing workbook bytes remain unchanged. All 77 tests passed after the change, and an actual offline demo generated the expected 3 opportunities, 2 discarded/excluded rows and 1 duplicate in this Linux/WSL environment. The user's Windows rerun is pending; this is not yet a successful native-Windows runtime verification.
